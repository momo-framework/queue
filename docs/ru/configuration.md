# Конфигурация

Значения по умолчанию лежат в `config/queue.php` и мёржатся под ключом `queue`.
Опубликуйте и переопределите их в `config/queue.php` вашего приложения.

## `backoff` — дефолтный ритм повторов

Применяется к повторяемым задачам, которые **не** реализуют `HasBackoffPolicyInterface`.

| Ключ           | Тип        | По умолчанию | Значение                                       |
|----------------|------------|--------------|------------------------------------------------|
| `base_seconds` | `int≥1`    | `5`          | Задержка перед первым повтором.                |
| `max_seconds`  | `int≥base` | `3600`       | Потолок, который не превысит ни одна задержка. |
| `multiplier`   | `float≥1.0`| `2.0`        | Множитель роста на каждый следующий повтор.    |

Задержка для попытки *n* (n≥2): `min(max_seconds, base_seconds * multiplier^(n-2))`.
С дефолтами: задержки повторов — `5, 10, 20, 40, …` секунд, с потолком в один час.

Некорректные значения приводятся к безопасным границам в `QueueServiceProvider`
(`base ≥ 1`, `max ≥ base`, `multiplier ≥ 1.0`).

## `worker` — дефолтные лимиты рантайма

Используются флагами `queue:work` (флаги CLI приоритетнее конфига).

| Ключ              | Тип     | По умолчанию | Значение                                                  |
|-------------------|---------|--------------|-----------------------------------------------------------|
| `sleep_seconds`   | `int≥0` | `1`          | Ожидание простоя, когда нечего обрабатывать (`--sleep`).  |
| `memory_limit_mb` | `int≥0` | `256`        | Воркер выходит при превышении RSS; `0` отключает (`--memory`). |
| `max_jobs`        | `int≥0` | `0`          | Обработать столько задач и выйти; `0` = без лимита (`--max-jobs`). |

## Консольные флаги

```bash
php bin/console queue:work --once            # maxJobs=1, stopWhenEmpty=true
php bin/console queue:work --max-jobs=1000   # перезапуск воркера после 1000 задач
php bin/console queue:work --sleep=2         # опрос простоя каждые 2с
php bin/console queue:work --memory=512      # порог перезапуска 512 МБ
```

## Подменяемые биндинги

Все биндинги по интерфейсам, поэтому провайдер приложения может переопределить
любой из них до boot:

| Интерфейс                  | По умолчанию                |
|----------------------------|-----------------------------|
| `QueueInterface`           | `InMemoryQueue`             |
| `FailedJobStoreInterface`  | `InMemoryFailedJobStore`    |
| `BackoffPolicyInterface`   | `ExponentialBackoffPolicy`  |
| `SleeperInterface`         | `CoroutineSleeper`          |
| `ClockInterface`           | `SystemClock`               |

Для межворкерной устойчивости замените `QueueInterface` и
`FailedJobStoreInterface` на персистентные (Redis/БД) реализации.
